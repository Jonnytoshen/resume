#### 多平台令牌托管服务 token-service ｜ 独立开发 ｜ 2025.01

**技术栈**：Python、FastAPI、Playwright、2Captcha、APScheduler、Redis、httpx、Docker

**背景与方案**：上游业务系统需要持续调用远景 Greenwich、金风 FreeMeso 两个风电资产平台的数据接口，而这些平台仅支持「账号密码 + 验证码」的网页登录且会话有效期短。服务把多平台登录与会话续期从业务代码里剥离出来统一托管：以 Provider Protocol 抽象登录 / 刷新 / 带令牌请求三项能力，平台差异集中在各自实现；登录由 Playwright 驱动无头 Chromium 完成，验证码交给 2Captcha；令牌写入 Redis 并由 APScheduler 定时预热，使登录开销不进入请求路径。

- 设计 provider 抽象与注册表，新增平台只需实现三个方法；已实现 Greenwich 字符验证码与 FreeMeso 滑块验证码两套登录流程。
- 实现令牌的单次并发刷新：双重检查 + `asyncio.Lock` + inflight future，同一平台的并发请求只触发一次登录；命中 401 强制刷新并重放请求，调用方无需感知令牌失效。
- 自动处理两类验证码：文字验证码截图后交 2Captcha 识别回填；滑块按原图与滑块宽度换算拖拽距离，用 30 段插值轨迹模拟人工拖动，并监听校验接口响应判定成败。
- 以 `storage_state` 复用会话，配合定时预热与提前量判断（30 秒 / 60 秒）减少重复登录，Redis TTL 支持多实例共享令牌。

**结果**：两个数据源收敛为一个接入入口，业务侧不再各自维护平台账号与登录代码，数据接入由人工登录取数转为服务自动完成；服务已容器化（镜像内置 Chromium 与 Playwright 依赖），对外提供健康检查、数据代理 GET / POST、手动刷新共 4 个端点。

#### Agent OS ｜ 独立开发 ｜ 2026.08 – 2026.10

**技术栈**：TypeScript、Node.js、飞书开放平台 SDK、MCP SDK、Claude Code / Codex CLI

**背景与方案**：把飞书当作 AI 编程 CLI 的指挥台——一个话题对应一个任务，多个机器人按角色（助理 / 产品 / 开发）组成团队互相 @ 协作，并按 cron 定时巡检，让「发起任务、确认方案、接收结果」都发生在 IM 里。常驻 Node 进程通过飞书长连接接收消息，按话题维护会话并把任务交给 CLI 子进程执行，解析其事件流后实时回写为可交互卡片；同时自建 MCP Server，把四项能力反向暴露给被调用的 CLI，形成人机双向的审批闭环。

- **CLI 适配层**：统一 Claude Code 与 Codex 两套事件协议，抽象出「启动 → 流式事件 → 工具调用 → 结果」的统一时序；支持跨消息续接会话、上下文压缩与 token 统计。
- **会话与任务编排**：以话题为任务边界维护会话状态与子进程生命周期，任务可并发推进、可中断续接；子进程异常退出时保留现场，重发消息即可在同一上下文里继续。
- **流式上屏与节流**：工具调用事件实时渲染为任务卡片，按固定间隔节流并串行写入，规避飞书卡片更新频控与并发写入导致的乱序覆盖。
- **多角色协作与定时巡检**：配置驱动注册角色、技能与独立工作区，@ 即可交接任务与评审；cron 三类规则与运行记录持久化，配套可注入故障的日志靶场验证巡检链路本身是否可靠。

**结果**：交付 v0.1.0–v0.5.0 五个版本，由单 bot 回声演进到多角色团队协作与方案审批闭环，打通「需求澄清 → 方案确认 → 实现 → 代码审查」完整链路；沉淀 7 个 Agent 技能，作为日常开发入口使用。

## 个人评价

- **端到端交付，不需要别人补位。** 从需求拆解、领域建模、接口与页面实现，到数据库迁移、容器化部署、域名备案与证书，一个人能把一件事从头收到尾。重途从零到 v0.2.0 用了 16 天，354 项回归和验收台账一并交付，不习惯把收尾留给下一个人。
- **接口先定，页面后写。** 前后端同一个人做的时候，先定 BFF 的输入输出、错误码与状态流转，再动手写页面，返工最少；羲和的报告生成链路与重途的线路测算都是按这个顺序落下来的。
- **数据模型宁可直接。** 领域规则不塞进 controller，也不藏在页面里：能进 domain 包的进包，能用不变量与快照约束的就不打补丁；迁移写进 `user_version`，每一步可重放。
- **用工程手段对抗不确定性。** 稳定性来自约束的设计，不来自运气：业务系统靠门禁、回归基线与可重放的验收记录，Agent 靠循环上限、工具契约与上下文预算。
- **选型看约束，不跟热度。** 从 Angular 全家桶走到 Next.js / NestJS / FastAPI，换栈不犹豫；但选型本身偏保守——bundle 体积、弱网带宽、单机能否部署，往往比框架新不新更能决定方案。
- **愿意把东西写下来。** 组件库的 TSDoc 与 104 个可交互示例、7 个 Agent 技能、接口契约与领域文档，都是主动沉淀的产物；评审过外部贡献者的 PR，也给其他团队做过前端技术支持。
